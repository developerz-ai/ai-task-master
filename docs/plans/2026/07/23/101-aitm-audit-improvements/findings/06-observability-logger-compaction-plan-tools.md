# Findings — observability/ + logger/ + compaction/ + plan/ + tools/ (+ index, testing)

> Raw report from parallel audit agent. Scope: `packages/aitm/src/{observability,logger,compaction,plan,tools,testing}/` + root `index.ts`.

## Bugs / correctness

- [severity: high] [category: bug] `src/observability/step-progress.ts:235-255,282,290` — Model text and tool inputs (e.g. a `bash` command containing `curl -H "Authorization: Bearer …"`) are written to stderr via `summarizeToolInput`/`renderStepLines` with only ANSI/control stripping, never `scrubSecrets` — the logger scrubs secrets meticulously (`logger.ts:104,164`) but the far chattier progress stream on the same fd does not, so secrets leak into terminal scrollback and any teed log file; run `clip()` output through `scrubSecrets` before emit.
- [severity: high] [category: bug] `src/compaction/compaction-step.ts:144-152` — The prune path skips the summarizer whenever `freedChars >= 20_000` (absolute) without re-checking that the pruned array now fits `usableInputTokens`, so a context overflowing by far more than ~5k tokens is still sent overflowing and the next model call fails on a window error; recompute the estimate over `pruned.messages` and fall through to summarize when it still exceeds the usable budget.
- [severity: med] [category: bug] `src/compaction/compaction-step.ts:91,204-213` — `estimateTokens` uses raw `JSON.stringify(message.content)` outside any try/catch, so a circular or BigInt-bearing SDK message throws straight out of `prepareStep` and crashes the step — the exact hazard `compactor.ts:198-202` documents and guards against in `safeStringify`; reuse `safeStringify` here.
- [severity: med] [category: bug] `src/tools/datetime.ts:41-50` — The tool's description promises the time "optionally formatted for a specific timezone" but `execute` always returns `date.toISOString()` (UTC) and only uses `Intl.DateTimeFormat` to echo the timezone name, so a model asking for Europe/Berlin gets a UTC instant labeled "Europe/Berlin" — actively misleading; return `formatter.format(date)` alongside the ISO instant. The test at `datetime.test.ts:23` bakes the wrong behavior in.
- [severity: med] [category: bug] `src/observability/error-reporter.ts:32-50` — `scrubEvent` claims to catch secrets in "stack frames" but only scrubs `exception.value`, `message`, `request.url`, and `breadcrumb.message`, missing `stacktrace.frames[].vars`, `breadcrumb.data`, `event.extra`, `event.tags`, and `event.contexts` — all of which the Sentry SDK populates and ships to GlitchTip unscrubbed; walk those fields too.
- [severity: med] [category: bug] `src/logger/secret-scrubber.ts:15` — The vendor-prefix pattern `gh[pousr]_` misses GitHub fine-grained PATs (`github_pat_…`) and underscore-form keys like Stripe `sk_live_`/`sk_test_` (only `sk-` with hyphen matches); add `github_pat_` and `(?:sk|pk|rk)_(?:live|test)_` alternatives.
- [severity: med] [category: bug] `src/compaction/compaction-step.ts:131-134` — On every compaction the original user task brief (goal + acceptance criteria) always lands in `older` and is replaced by the LLM summary, relying entirely on the summarizer to preserve the contract; keep the run's first user message verbatim ahead of the summary so the ground-truth task can never degrade through successive summarizations.
- [severity: low] [category: bug] `src/tools/web-fetch.ts:235-239` — `readBodyCapped` sets `truncated = body.length > maxChars` after the `>=` check, so a stream cancelled exactly on `maxChars` reports `truncated: false` even though more data remained; treat reaching the cap with an unfinished stream as truncated.
- [severity: low] [category: bug] `src/plan/plan-markdown.ts:46-53` — Task lines before any `## Group:` header are silently dropped (`current` undefined), and a hand-edited task whose text begins with a bracketed word (`- [ ] [FOO] fix x`) silently loses `[FOO]` to the complexity slot; count/return orphan lines or warn on unknown complexity tags.
- [severity: low] [category: bug] `src/plan/schema.ts:72-76` — `PlanSchema.groups` has no `.min(1)`, so an empty plan validates and only fails later at `subagents/planner.ts:124` — outside the schema-retry loop the file itself says is the cheap enforcement point; add `.min(1)` with a `.describe()`.
- [severity: low] [category: bug] `src/observability/run-step.ts:72-78` — In prPerTask mode a task id absent from the group clamps `findIndex` −1 to 0 (silently reporting the group's first task) and the done-count fallback yields `before+done+1`, one past the last task once a group completes; return `undefined` for unknown tasks and clamp the fallback.
- [severity: low] [category: bug] `src/tools/github-thread-tool.ts:46-48` — A missing/blank `body` for `replyToThread` returns bare `{ ok: false }` with no reason; include an error string.
- [severity: low] [category: bug] `src/tools/web-fetch.ts:151-159` — The SSRF IPv4 denylist misses 100.64.0.0/10 (CGNAT — metadata endpoints on some clouds), 192.0.0.0/24, 198.18.0.0/15, and NAT64 `64:ff9b::/96`; extend the range checks. (Fetch-path DNS-rebind TOCTOU at 73-77 documented as accepted; residual risk only.)
- [severity: low] [category: bug] `src/logger/logger.ts:67-69` — `status()` writes to stdout without `scrubSecrets`, the one Logger output path with no redaction at all; scrub status messages too.

## Missing resource cleanup / lifecycle

- [severity: med] [category: resource] `src/logger/logger.ts:77-84` vs `src/cli/cli.ts:197-207` — The CLI exit path awaits `reporter.flush()` but never a `Logger.flush()`, and `process.exit()` would discard pending `writeTail` file appends; wire logger flush into the same shutdown path.
- [severity: med] [category: resource] `src/observability/usage-tracker.ts:101-166` — Usage/cost accounting lives only in memory and is flushed solely on normal loop completion (`cli/commands.ts:505`); a crash or second-SIGINT force-exit loses the run's entire spend record — persist increments to state or flush totals in the signal/exit handler.
- [severity: low] [category: resource] `src/observability/heartbeat.ts:55-58` — The default `setInterval` handle is never `unref`'d; call `handle.unref?.()` as defense in depth (all five current call sites do `finally { stop() }` correctly).
- [severity: low] [category: resource] `src/observability/error-reporter.ts:61-89` — `Sentry.init` is never paired with `Sentry.close()`; `flush(2000)` drains events but leaves global integrations/handlers installed — wrong if `main` is ever embedded (it is exported from `index.ts:5`); return a `close()` on the reporter.

## Architecture / house rules

- [severity: med] [category: arch] `src/logger/logger.ts:40` — `new Logger(...)` appears nowhere in production code (only tests); every consumer takes `logger?: LoggerLike` and no CLI/loop site ever supplies one, so the entire structured-logging module — level filter, file transport, redaction — is dead code in the shipped binary, and every `logger?.warn` (e.g. compaction failure warnings at `compaction-step.ts:110,161,172`) is a silent no-op; construct a Logger in `cli/commands.ts` and thread it through the run.
- [severity: med] [category: arch] `src/loop/run-loop-adapter.ts:1275-1279,1378-1382` — The two main-path `buildCompactionStep` call sites (worker, reviewer) omit `logger` entirely while `ci-fix.ts:275` and `self-review.ts:211` at least thread the (never-populated) optional — so compaction skip/failure diagnostics are structurally unreachable exactly where compaction matters most; pass the run logger at all four sites.
- [severity: med] [category: arch] `src/compaction/compaction-step.ts:85-90` — Because the `prepareStep` message override doesn't persist, every step after the threshold re-runs the full prune + (when under 20k freed) a fresh LLM summarizer call against the reverted full history — a per-step summarizer bill acknowledged in the comment as a "follow-up"; cache the last compacted result keyed on message-array length and reuse it until the tail grows past budget.
- [severity: low] [category: arch] `src/observability/step-progress.ts:1-435` — One 435-line module holds five responsibilities (duration/tag formatting, label composition, sink abstraction, step renderer, live-stream renderer, handler composition); split into format/label, sink, and renderer modules.
- [severity: low] [category: arch] `src/logger/logger.ts:146-165` and `src/compaction/compactor.ts:203-213` — Two bespoke cycle-safe serializers solve the identical problem (both citing issue #251) with different mechanisms (WeakSet ancestor chain vs `JSON.stringify` holder walk); extract one shared helper.
- [severity: low] [category: arch] `src/index.ts:30-44` — The "keep this list narrow" public surface re-exports test-only internals (`decodeDdgHref`, `parseDuckDuckGoHtml` — both annotated "Exported for unit testing" — plus `DEFAULT_STEALTH_HEADERS`, `DEFAULT_IMPERSONATE_TARGETS`); tests can import from the module path directly, so drop them from the index.

## Tests

- [severity: low] [category: test] `src/compaction/compaction-step.test.ts` — No test covers (a) prune freeing ≥20k while the result still exceeds the budget, or (b) a circular/BigInt message hitting `estimateTokens`; both are the crash/overflow paths above.
- [severity: low] [category: test] `src/observability/error-reporter.test.ts:1-65` — Only the no-DSN and pure-function paths are tested; the DSN-present branch (SDK import, `beforeSend` wiring, flush) is entirely unexercised.
- [severity: low] [category: test] `src/testing/temp-repo.ts:19` — `git init` without `-b main` leaves the branch name to host `init.defaultBranch`, making dependent tests environment-sensitive; pin the branch.
- [severity: low] [category: test] `src/index.test.ts:5-23` — The surface test asserts presence of ~16 exports but neither the tool exports nor absence of unintended ones, so surface drift in either direction passes silently.

House-rule scan: no `any`, no `as unknown as`, no default exports, no `Bun.*` APIs in any audited shipped file; every audited module has a paired `*.test.ts` and coverage is generally strong (logger, step-progress, web-fetch SSRF, and compactor suites notably thorough).

## Missing capabilities worth adding

- **Env-value secret scrubbing**: scrub the literal runtime values of `OPENROUTER_API_KEY`/known credential env vars from every output channel (logger, progress stream, GlitchTip events) — pattern-based scrubbing cannot catch arbitrary-format keys from custom OpenAI-compatible endpoints, which the provider stance explicitly supports.
- **Unified shutdown path**: one exit hook that flushes Logger, UsageTracker totals, and the error reporter together on normal exit and on first signal, so no telemetry/accounting channel depends on its caller remembering to flush.
- **Post-compaction size verification**: after prune or summarize, re-estimate the outgoing context and escalate (summarize, then hard-truncate oldest tail) until it provably fits the usable window, turning the current heuristic into a guarantee.
