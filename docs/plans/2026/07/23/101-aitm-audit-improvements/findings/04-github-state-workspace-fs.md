# Findings — github/ + state/ + workspace/ + fs/

> Raw report from parallel audit agent. Scope: `packages/aitm/src/{github,state,workspace,fs}/`.

## Bugs / correctness

- [severity: high] [category: bug] `packages/aitm/src/workspace/in-place-checkout.ts:145-153` — `ensureCleanTree` runs `git reset --hard` + `git clean -fd` on every `acquire`/`resetToBase`, so a user's pre-existing uncommitted work at run start is destroyed indistinguishably from "stale group junk"; refuse to start (or auto-stash) on a dirty tree at run entry and only auto-clean between groups.
- [severity: high] [category: bug] `packages/aitm/src/state/state-store.ts:24-77` — there is no cross-process lock anywhere (grep confirms no lockfile/flock in cli/loop/state), so two concurrent `aitm` runs on the same state dir do last-writer-wins on `state.json`, and the in-memory `cached` (line 39) never observes peer writes, guaranteeing lost updates; `transcript-store.ts:237` even anticipates "a peer sharing the state dir" — acquire an exclusive `run.lock` (open `wx` + pid) in init/resume with try/finally release.
- [severity: med] [category: bug] `packages/aitm/src/github/github-client.ts:49-58` — `defaultRunCmd` flattens every `ExecaError` — including spawn ENOENT (gh not installed) — into `{exitCode: 1, stderr: ''}`, so callers throw e.g. `gh pr view failed: ` with an empty message and `GhCliMissing` is never raised; detect `err.code === 'ENOENT'` → throw `GhCliMissing`, and surface `shortMessage`.
- [severity: med] [category: bug] `packages/aitm/src/github/github-client.ts:251-254` — one transient gh failure (network flake → empty/non-JSON stdout) mid-poll throws and aborts a wait that may be 2h in; there is no retry-on-failure in `waitForChecks` (the backoff only paces successful polls) — tolerate N consecutive poll failures before throwing.
- [severity: med] [category: bug] `packages/aitm/src/github/github-client.ts:251-268` — the empty-check-set grace path assumes `gh pr checks` emits literal `[]`; gh versions that report "no checks reported" via non-zero exit + empty stdout hit `tryParseChecks → null` and throw at line 253 instead of entering `CHECKS_EMPTY_GRACE_MS`, so a checkless PR can hard-fail rather than merge — recognize the "no checks" stderr as an empty row set (no test covers this case either).
- [severity: med] [category: bug] `packages/aitm/src/github/github-client.ts:70-73` — `isInstantSleepEnabled` keys production sleep behavior off ambient `NODE_ENV === 'test'`, so a run launched in an environment that happens to set it collapses `CHECKS_START_WAIT_MS`/`CHECKS_EMPTY_GRACE_MS` to zero and can read a just-pushed PR's empty check set as mergeable; require the explicit `AITM_INSTANT_SLEEP` opt-in only.
- [severity: med] [category: bug] `packages/aitm/src/github/github-client.ts:313-327` — `failedRunIds` uses `gh run list --limit 30` with no pagination; on a branch with many workflows the failed run can fall outside the newest 30 and `getFailedCiLogs` silently returns `[]` ("no logs" fed to the fix loop) — filter server-side by head SHA or paginate.
- [severity: med] [category: bug] `packages/aitm/src/github/github-client.ts:432-434` — the non-advancing-cursor guard returns *before* adding the current page's nodes, silently dropping that page's threads (same pattern at 476-477 for comments), and `MAX_REVIEW_THREAD_PAGES` exhaustion at 438-439 truncates with no warning; append the page's nodes before breaking and log on truncation.
- [severity: med] [category: bug] `packages/aitm/src/state/state-store.ts:224-226` — `legacyTask` derives ids as `slugify(text)`, so two legacy tasks with identical text get identical ids, and the `Aitm-Task-Id` trailer resume dedup (`workspace/in-place-checkout.ts:53-72`) then reports the second task done because the first's commit matches — suffix the index into every legacy id, not just the empty-slug case.
- [severity: med] [category: bug] `packages/aitm/src/state/schema.ts:111-135` — `RunStateSchema` has no `schemaVersion` field; migration is ad-hoc read-time coercion (`state-store.ts:212-248`) that cannot distinguish "legacy" from "corrupt" and will accrete per-field hacks (five `optional`/`default` legacy escapes already) — add a version field plus a small keyed migration table.
- [severity: med] [category: bug] `packages/aitm/src/workspace/git-exec.ts:46-47` — `assertGitAllowed` only fires when `args[0] === 'push'`, so `['-C', dir, 'push', '--force']` or `['-c', 'k=v', 'push', '-f']` bypasses the advertised force-push chokepoint; skip leading global options before locating the subcommand.
- [severity: low] [category: bug] `packages/aitm/src/github/github-client.ts:572` — the merge-conflict classifier regex includes bare `conflict`, so any gh error merely containing that word (e.g. a ref/label conflict message) is misreported as `MergeConflict`; keep only the specific phrases.
- [severity: low] [category: bug] `packages/aitm/src/github/github-client.ts:240-276` — `waited` excludes the initial `CHECKS_START_WAIT_MS` and each gh call's latency, so the "120 min" budget is wall-clock-inaccurate (loosely unbounded on slow gh calls); accumulate from a `Date.now()` anchor.
- [severity: low] [category: bug] `packages/aitm/src/state/pr-context-store.ts:101-110` — `readAddressedThreads` swallows *every* error (EACCES, corrupt JSON) into an empty set, so the review loop would re-reply to all already-addressed threads; only ENOENT should degrade to empty.
- [severity: low] [category: bug] `packages/aitm/src/state/pr-context-store.ts:46-97` — `saveCiFailures`/`saveComments` never purge their subdir, so if a caller skips `clear()` between polls, stale `failed_*.txt`/`NNN_*.txt` from a previous iteration survive alongside fresh ones and mislead the fix subagent; have each save clear its own subdir first.
- [severity: low] [category: bug] `packages/aitm/src/state/rolling-context.ts:46-55` — `capOldestFirst` assumes `\n\n` only ever separates whole blocks, but the `existing` string can come from `StateStore.writeContext` content it didn't author (an LLM summary with blank lines), mis-splitting into pseudo-blocks and dropping partial text; normalize/collapse blank lines in `existing` before splitting.
- [severity: low] [category: bug] `packages/aitm/src/workspace/task-commit-marker.ts:11-13` — `taskCommitTrailer` accepts raw planner-derived ids; an id containing a newline can never match the full-line check in `in-place-checkout.ts:69-71`, silently disabling resume dedup for that task — sanitize/reject non-line-safe ids at trailer build time.
- [severity: low] [category: bug] `packages/aitm/src/state/state-store.ts:43-48` — `init` unconditionally overwrites an existing `state.json`, so a mistaken second `aitm start` clobbers a resumable run at the store layer regardless of CLI guards; make init refuse (or require explicit force) when state exists.

## Resource cleanup

- [severity: med] [category: resource] `packages/aitm/src/github/github-client.ts:41-59` — no gh invocation carries a `timeout` or `AbortSignal` (execa called with only `cwd`), so a hung `gh api .../logs` or a stalled `gh pr checks` blocks the run forever — `CHECKS_TIMEOUT_MS` bounds loop iterations, never a single child process; pass execa `timeout`/`signal` through `RunCmdOptions` and kill on abort.
- [severity: low] [category: resource] `packages/aitm/src/state/state-store.ts:105-114` — `appendProgress` uses bare `appendFile` (no fsync, non-atomic), so a crash can leave a torn final line in `progress.md`; acceptable for a log but worth noting against the module header's "atomic writes" claim (line 2).
- [severity: low] [category: resource] `packages/aitm/src/state/transcript-store.ts:169-171` — `end()` is best-effort like any append: if only the final `run-end` write fails (fewer than 3 consecutive failures, so no marker), a *completed* transcript looks interrupted and `findResumable` (line 298) replays a finished conversation; retry or fsync the run-end record specifically.
- [severity: low] [category: resource] `packages/aitm/src/state/transcript-store.ts:238-251` — `reserveOrdinalFile` intentionally leaves empty reserved `.jsonl` files when an agent dies before its first step and nothing ever garbage-collects them (findResumable only skips them, line 293); prune empty ordinals during `begin` or cleanup.
- (Positive note: `fs/atomic-write.ts` is correct — `wx` temp + fsync + rename + parent-dir fsync with try/finally close and temp removal on both failure paths; no findings there.)

## Architecture

- [severity: med] [category: arch] `packages/aitm/src/github/github-client.ts:122-607` — one 857-line class carries five concerns (PR CRUD, checks polling + backoff policy, CI log download, GraphQL review-thread pagination, auth/scopes); split at least the checks-poller and review-thread reader into their own modules so polling policy is testable apart from transport.
- [severity: low] [category: arch] `packages/aitm/src/github/errors.ts:3-21` — `PrNotFound`, `ReviewThreadStale`, `GhCliMissing`, `GhAuthRequired` are exported but never thrown anywhere (grep-confirmed); the file header promises "never raw stderr; always domain errors" yet nearly every client throw is `new Error(\`gh … failed: ${stderr}\`)` — either wire the domain errors in or delete them.
- [severity: low] [category: arch] `packages/aitm/src/github/github-client.ts:162-175` — `defaultBranch` hand-rolls JSON narrowing while every sibling (`repoMeta` line 550, checks line 707, GraphQL line 422) uses Zod; use a `DefaultBranchSchema` for consistency.
- [severity: low] [category: arch] `packages/aitm/src/state/pr-context-store.ts:136-138` — the `sanitize` helper is duplicated verbatim in `transcript-store.ts:51-53` (its comment even says "mirroring PrContextStore.sanitize"), with a third slug variant at `state-store.ts:250-257`; extract one fs-safe-name util per the house "second real caller" rule.
- [severity: low] [category: arch] `packages/aitm/src/github/check-tolerance.ts:74` — `envRules()` re-parses the env var inside the per-rule loop's enclosing call, i.e. on every failed check row of every poll; parse once per process (or memoize) since the env cannot change mid-run.
- [severity: low] [category: arch] `packages/aitm/src/github/github-client.ts:218-220` — `createPr` spawns one `gh label create --force` per label on every PR creation even though labels are repo-level and never change mid-run; ensure-once per run (cache like `cachedRepoMeta`).

## Tests / house rules

- [severity: low] [category: test] `packages/aitm/src/github/errors.ts` and `packages/aitm/src/github/schema.ts` — neither has a paired `*.test.ts` (errors asserted only incidentally at `github-client.test.ts:69`), violating the "every module ships with tests" rule.
- [severity: low] [category: test] `packages/aitm/src/state/state-store.test.ts` — no test exercises two StateStore instances (or processes) over the same dir, so the cache-vs-disk lost-update hazard (`state-store.ts:39`) is untested; likewise `github-client.test.ts` has no case for a transient mid-poll gh failure or a non-zero "no checks reported" exit in `waitForChecks`.
- [severity: low] [category: test] `packages/aitm/src/state/transcript-store.ts:100` — `console.debug` writes to stdout in Node, violating the Logger contract (structured logs → stderr, stdout reserved for plain status) and polluting parseable CLI output; route through the store's `onWarn`/Logger debug path.
- Portability: clean — no `Bun.*` APIs, no `any`/`as unknown as`, no default exports anywhere in the four audited dirs (grep-verified).

## Missing capabilities worth adding

- A run-level exclusive lock file for `.ai-task-master/` (pid + heartbeat) so concurrent `aitm` invocations fail fast instead of silently corrupting shared state — transcript-store already half-designs for peer processes; state-store doesn't.
- Abort/timeout plumbing through `RunCmd` (execa `signal`/`timeout`) plus one centralized transient-failure retry policy for gh calls, so Ctrl-C/timeout reliably kills children and a single network flake can't abort a 2-hour CI wait.
- `schemaVersion` in `state.json` with a keyed migration table (and ideally an `aitm doctor`-style validate command) replacing the growing pile of read-time coercions and per-field `optional()` legacy escapes.
