# Findings — mcp/ + openrouter/ + credentials/ + agent-config/

> Raw report from parallel audit agent. Scope: `packages/aitm/src/{mcp,openrouter,credentials,agent-config}/` (+ `@ai-sdk/mcp` stdio transport internals and CLI call sites).

## mcp/

- [severity: high] [category: bug] `src/mcp/mcp-client.ts:76-77` — `connectAll()` awaits `createClient()` and `client.tools()` with no timeout, so one MCP server that hangs mid-handshake (wedged stdio child, unresponsive HTTP endpoint) blocks run startup forever, defeating the stated "a broken MCP server should not block the whole run" contract; wrap each server's connect in a `Promise.race` with a per-server deadline and close the client on expiry.
- [severity: med] [category: resource] `src/mcp/mcp-client.ts:135-149` — `close()` awaits `Promise.all` of `client.close()` calls with no timeout, so a single hanging `close()` means `this.processes.terminate()` on line 149 is never reached — directly contradicting the comment on lines 147-148 ("a client.close() that hangs ... must not decide whether the child process survives"); time-box the close batch and always run `terminate()` after.
- [severity: med] [category: resource] `src/mcp/mcp-client.ts:80-99` — on the `tools()`-throws path, `client.close()` (line 82) runs before the `finally` reads the pid, and the SDK's `StdioMCPTransport.close()` and child-`close` handler both set `this.process = void 0`, so `stdioPid()` returns undefined and the pid is never registered for exactly the mid-handshake-failure case the line 95-97 comment claims to cover; snapshot the pid immediately after `createClient` resolves, before any close.
- [severity: low] [category: bug] `src/mcp/mcp-client.ts:206-209` — `sanitizeServerName` maps distinct configured names to the same key (`my-srv` and `my__srv` both → `my-srv`; `a b` and `a-b` both → `a-b`), silently overwriting one server's tools in the merged `ToolSet` with the other's; detect post-sanitization collisions and warn or de-duplicate with a suffix.
- [severity: low] [category: bug] `src/mcp/mcp-client.ts:69-101` — servers connect strictly sequentially, so N slow servers serialize startup latency; connect concurrently (`Promise.allSettled`) since failures are already isolated per server.
- [severity: low] [category: bug] `src/mcp/tool-search.ts:184-186` — a deferred tool that has no `execute` returns the "fetch its schema with tool_search first" guard even after activation, sending the model into a fetch/call loop it can never exit; return a distinct "tool is not executable" message for the `!baseExecute` case.
- [severity: low] [category: arch] `src/mcp/tool-search.ts:200` — `guardDeferred` returns `{ ...base, execute, toModelOutput } as AnyTool` — a soft cast that erases the `Tool` generic typing; model the wrapper with a generic over the base tool instead of casting.

## mcp/oauth.ts (biggest problem cluster)

- [severity: high] [category: arch] `src/mcp/oauth.ts:167-267,296-297` — this module ships an inbound localhost HTTP server (`NodeServer` + `http.createServer`), and CLAUDE.md's "Out of scope for v1" explicitly bans "Webhooks or any inbound HTTP" with instructions to stop and surface rather than implement; needs an explicit sanction (RFC 8252 loopback-redirect exception) or removal — surfaced as required.
- [severity: high] [category: bug] `src/mcp/oauth.ts:282-293` — the authorization request sends no PKCE `code_challenge` (and no `code_verifier` at token exchange, lines 343-348) even though the file header cites "MCP OAuth 2.1 spec" — OAuth 2.1/MCP make PKCE mandatory, so spec-compliant servers will reject the flow and the loopback redirect is open to code interception; generate an S256 challenge/verifier pair.
- [severity: med] [category: bug] `src/mcp/oauth.ts:234,254-256` — `Object.fromEntries(searchParams) as OAuthCallbackResult` is an unvalidated cast: a callback with neither `code` nor `error` (e.g. `/callback?state=x`) resolves the flow and posts `code=undefined` to the token endpoint; validate that `code` or `error` is actually present before resolving.
- [severity: med] [category: bug] `src/mcp/oauth.ts:325` + `src/cli/commands.ts:969-971` — `config.url` is derived by stripping `/oauth/authorize.*` off `authUrl` (built from `serverUrl.origin`), so an MCP server at `https://host/mcp` produces a config snippet pointing at `https://host` — the wrong server URL; pass the original server URL through `OAuthOptions` instead of reverse-engineering it.
- [severity: med] [category: bug] `src/mcp/oauth.ts:107-109` — `fileURLToPath(join(dirname(import.meta.url), ...))` mixes a `file://` URL string through `path.join` (collapses `///`, backslashes on Windows) and sits *outside* the `try`, so a parse failure throws out of `loadHtmlTemplate` instead of hitting the fallback; use `fileURLToPath(new URL('../templates/…', import.meta.url))` inside the try.
- [severity: med] [category: resource] `src/mcp/oauth.ts:199-206` — `stop()` awaits `server.close()`, which only completes after all connections close; a browser keep-alive connection makes the `finally` on line 330-332 hang indefinitely; call `server.closeAllConnections()` (Node ≥ 18.2) before awaiting close.
- [severity: med] [category: bug] `src/mcp/oauth.ts:272-276` — a caller-supplied `callbackUrl` does not inform the listening port: the server binds an auto-picked port in 8787-9000 while `redirect_uri` points wherever `callbackUrl` says, so the callback never reaches the server and the flow times out; parse and use the port from `callbackUrl` when provided.
- [severity: low] [category: bug] `src/mcp/oauth.ts:362-373` — the token response is checked only for an `error` key and then `as`-cast; a 200 response without `access_token` yields `Authorization: Bearer undefined`; validate `access_token` is a non-empty string.
- [severity: low] [category: bug] `src/mcp/oauth.ts:237-245` — a state-mismatch callback returns 400 to the browser but never settles `waitForCallback`, so the CLI silently hangs until the full timeout with no operator-visible signal; log/report the mismatch while continuing to wait.
- [severity: low] [category: arch] `src/mcp/oauth.ts:54-58,271` — `detectRuntime()` is computed and never used, `ServerImpl` is an interface with exactly one implementation, and `rejecter` (lines 222-226) is assigned but never invoked — dead code implying Bun/Deno servers that don't exist, and duplicating `detectRuntime` from `src/credentials/llm-fetch.ts:40-46`; delete the dead paths or implement them.
- [severity: med] [category: test] `src/mcp/oauth.test.ts:6-14,16-28,30-50,52-72` — the pairing is near-worthless: it re-implements `generateState` instead of importing it, "structure" tests assert TypeScript type shapes at runtime, the two `performOAuthFlow` tests spawn a REAL browser (`xdg-open`) and bind real ports on every test run, and line 49 drops the `await` on `assert.rejects` (floating promise); no coverage exists for state validation, callback parsing, or token exchange — rewrite against an injected server/browser seam.

## openrouter/

- [severity: med] [category: bug] `src/openrouter/client.ts:106-108` and `src/openrouter/reference-catalog.ts:34` — both catalog fetches have no timeout/AbortSignal, and `ModelLimitsRegistry.fillFromReference`'s try/catch (`src/openrouter/model-limits.ts:137-142`) guards only rejection, not a hang — a stalled `/models` endpoint stalls `preload()` and therefore run startup indefinitely; pass `AbortSignal.timeout(...)` to both.
- [severity: low] [category: bug] `src/openrouter/model-limits.ts:152-158` — `hasGap` ignores `maxOutputTokens`, so a provider publishing window + pricing but no output cap never receives the reference catalog's `max_completion_tokens` even though `merge` (line 197-199) is ready to fill it; add it to the gap predicate.
- [severity: low] [category: arch] `src/openrouter/client.ts:109-111` vs `src/openrouter/reference-catalog.ts:35-39` — the fetch → `!res.ok` → body-excerpt → throw pattern is duplicated (with inconsistent excerpt caps, 500 vs 200); extract one shared `fetchCatalog(url, headers)` helper.

## credentials/

- [severity: low] [category: bug] `src/credentials/credentials.ts:60` — `onOpenRouter = !resolved.baseURL` means an *explicit* `baseURL` of `https://openrouter.ai/api/v1` silently disables cache_control, session_id, and usage accounting on the actual OpenRouter endpoint; also treat OpenRouter's own host as on-OpenRouter.
- [severity: low] [category: resource] `src/credentials/llm-fetch.ts:77-85` — the undici `Agent` (60s keep-alive, 16 connections) has no disposal path — nothing ever calls `close()/destroy()` on it — and the wrapper `{ ...init, dispatcher }` silently clobbers any caller-supplied `init.dispatcher`; return a dispose handle alongside the fetch and only inject the dispatcher when the caller didn't set one.
- [severity: low] [category: arch] `src/cli/commands.ts:507` and `src/loop/run-loop-adapter.ts:1213` — `new OpenRouterClient(resolved.openrouterApiKey, resolved.baseURL)` is wired at two call sites outside `Credentials`, spreading key+baseURL pairing beyond the "one place" the module map mandates; expose a catalog-client factory from `Credentials` (or one shared builder) instead.
- [severity: low] [category: test] `src/credentials/defaults.ts` — no paired `defaults.test.ts` (values asserted only incidentally via credentials.test.ts); add a minimal pairing or fold the table into credentials.ts.

## agent-config/

- [severity: low] [category: bug] `src/agent-config/agent-config-detector.ts:81-94` — the repoRoot containment check applies only to *relative* `stylePath`s; an absolute path outside the repo is accepted but then expanded with `root: this.repoRoot`, so every one of its relative `@`-imports silently fails containment and is left literal; if out-of-repo style files are intended, expand them rooted at their own directory (as `detectUser` does at lines 173-176).
- [severity: low] [category: bug] `src/agent-config/expand-imports.ts:144` — the `@([^\s]+)` pattern captures trailing prose punctuation (`see @docs/style.md.` → path `docs/style.md.`), so the realpath lookup fails and the import is silently left literal; strip trailing `.,;:!?)` from the captured path before resolving.
- [severity: low] [category: bug] `src/agent-config/agent-config-detector.ts:118` — `readdir(...).catch(() => null)` swallows EACCES/EIO the same as ENOENT, silently dropping entire subtrees of nested config files with no `onWarn`; warn on non-ENOENT readdir failures.

## Cross-cutting checks that came back clean

- No `Bun.*` APIs, no Anthropic-SDK-shaped code, no default exports, ESM throughout; `chatSettings`/`providerSettings` correctly centralize inference wiring in Credentials; API keys never appear in log/error strings; mcp-client.test.ts (487 lines), model-limits, expand-imports, and credentials test suites are genuinely thorough — tool-name-collision, allowlist, prototype-pollution, symlink-escape, and byte-budget edges all have direct tests.

## Missing capabilities worth adding

- **MCP connect/close deadlines as config**: a `connectTimeoutMs`/`closeTimeoutMs` on `McpClientInit` (with parallel connect) is the single change that removes the three hang-forever paths in mcp-client.ts.
- **OAuth completeness**: PKCE (mandatory), RFC 8414 authorization-server metadata discovery instead of hard-coding `/oauth/authorize`+`/oauth/token` (cli/commands.ts:970-971), and refresh-token capture — today the access token is printed once to stdout and expires with no recovery path.
- **Shared HTTP fetch helper with timeout+retry** for the two catalog clients (and any future keyless GET), replacing the duplicated non-2xx/excerpt logic and giving one place to add `AbortSignal.timeout`.
