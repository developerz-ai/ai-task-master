# Findings — cli/ + config/

> Raw report from parallel audit agent. Scope: `packages/aitm/src/{cli,config}/`.

## Bugs / correctness

- [severity: high] [category: bug] `config-loader.ts:160-163` — A project-scope `bashRules` wholesale-replaces the user's global deny rules and its `allow` entries win first-match over `DEFAULT_BASH_RULES` (config-loader.ts:70-76), so an untrusted checked-in `.ai-task-master/config.json` can re-enable `git push --force`/`gh pr merge` for the model shell even though the same loader strips `hooks`/`formatCommand`/`verifyCommand` as untrusted (config-loader.ts:54-64); treat project `bashRules` like the other untrusted fields (strip, or merge project rules *after* global deny rules and forbid project `allow` overrides of built-ins).
- [severity: med] [category: bug] `profiles.ts:77-84, 43, 57` — Profile *names* are never checked against `FORBIDDEN_KEY_SEGMENTS` and membership uses `in`/bracket access, so `aitm profile set __proto__ baseURL x` resolves `profiles['__proto__']` to `Object.prototype` and `setDotted` (profiles.ts:239-248) writes onto `Object.prototype` (in-process prototype pollution), while `profile use __proto__`/`use constructor` pass the `name in profiles` guard (profiles.ts:43) and persist a dangling `activeProfile`; validate names with `Object.hasOwn` and reject `FORBIDDEN_KEY_SEGMENTS` — ironic given provider-presets.ts:52-56 fixes exactly this for presets.
- [severity: med] [category: bug] `commands.ts:689-695` — `merge-pr --no-resume` with an existing state.json calls `state.init()` with a synthesized takeover state, and `StateStore.init` unconditionally overwrites (state-store.ts:43-48), destroying an in-progress run's `prGroups`/`runId`/plan linkage; the flag's contract is only "don't trust persisted currentPr", so it should update `currentPr` in place (or refuse when `prGroups` is non-empty) instead of clobbering the whole run. The test at commands.test.ts:1101-1135 blesses the overwrite but only seeds a bare `currentPr` state, never a mid-plan run.
- [severity: med] [category: bug] `config-writer.ts:29-39` — `aitm config set openrouterApiKey <key> --project` (likewise `formatCommand`, `verifyCommand`, `hooks`, `baseURL`, `stylePath`) succeeds, writing a secret/shell command into the repo-committable `.ai-task-master/config.json` that the loader then silently strips at run time (config-loader.ts:54-64); the writer should reject (or at minimum warn on) `UNTRUSTED_PROJECT_FIELDS` keys in project scope — export that list from config-loader and check scope-aware.
- [severity: med] [category: bug] `config-loader.ts:508-521 vs 528-543` — Base URL resolves global > profile while the key also resolves global > profile, so a stale top-level `baseURL` set via `aitm config set` silently overrides the freshly-activated profile's `baseURL` and the profile's API key is sent as a Bearer token to a *different provider's* host (e.g. z.ai key to openrouter.ai); when a profile is active and supplies the key, its baseURL should win or the mismatch should at least warn.
- [severity: med] [category: bug] `commands.ts:552-557` — On an idempotent `aitm start` re-run of an unfinished run, `args.criteria` (usually `undefined`) is passed to the loop instead of the persisted criteria, unlike `aitm resume` which restores it (commands.ts:642-646); runStart's resume branch should fall back to `state.readGoal().criteria` when the flag is absent.
- [severity: low] [category: bug] `args.ts:270-277` — There is no `--` end-of-options sentinel anywhere in the parser, so a goal/criteria/value beginning with `-` is unpassable (`aitm start "--fix the flag parser"` → usage error) and `config set <key> <value>` can never store a value starting with `--` (args.ts:363-371); support the conventional `--` separator.
- [severity: low] [category: bug] `cli.ts:163-174` — Help text has drifted from the parser: `--pr-per-task` and `--max-fix-attempts` (start, args.ts:229-253), `--max-iterations` (merge-pr, args.ts:332), and the `moonshot` preset (provider-presets.ts:9) are all accepted but undocumented; regenerate HELP_TEXT from the flag tables or add the missing lines.
- [severity: low] [category: bug] `args.ts:11,16` — `StartArgs.maxSessions?: number | null` and `stylePath?: string | null` declare `null` arms the parser never produces (the 0→null mapping happens later in commands.ts:1018-1019), schema drift between the arg type and the parser; narrow the parsed type and keep `null` only in `CliOverrides`.
- [severity: low] [category: bug] `args.ts:300-313` — `isValidBranchName` misses ASCII control chars (`\s` covers whitespace only, not `\x01`–`\x1f`/DEL) and the single-`@` ref git forbids, so such a `--branch` passes validation and fails later at `git checkout -B`; extend the regex with `[\x00-\x1f\x7f]` and reject `name === '@'`.
- [severity: low] [category: bug] `config-writer.ts:41-47` — `config unset <typo>` performs no `CONFIG_KEYS` check (unlike `set`, line 33) and silently exits 0 on a key that never existed; validate the top-level key so typos are surfaced.
- [severity: low] [category: bug] `commands.ts:1284` — `synthesizeTakeoverState` hardcodes `agentConfigFile: 'CLAUDE.md'` even when the repo only has AGENTS.md (detection happens later at commands.ts:737), persisting wrong provenance in state; derive it from the actual `detector.detect()` result.
- [severity: low] [category: bug] `args.ts:434-439 vs 373-379` — `profile set` accepts a *value* starting with `--` while `config set` rejects it (its flag loop consumes any `--` token), an inconsistent grammar between the two twin commands; unify once a `--` sentinel exists.

## Resource cleanup / RAII

- [severity: med] [category: resource] `cli.ts:201-209` — `process.exit(code)` immediately after `main()` can truncate buffered stdout/stderr when piped (Node does not flush async stream writes on `exit`), so long outputs like `config list` JSON or the PR-links block can be cut off in `aitm … | tee`; set `process.exitCode = code` and let the process drain, or await stream flush before exiting.
- [severity: med] [category: resource] `cli.ts:234-238` — The second-signal force path `proc.exit(128 + signo)` bypasses `reporter.flush()` (cli.ts:202) and any in-flight `atomicWrite`, losing the crash report and potentially a temp file; flush the reporter (bounded) in the force-exit branch, and remove the handlers once `main()` resolves so a late Ctrl+C doesn't print a meaningless "Cancelling" during final flush.
- [severity: low] [category: resource] `commands.ts:874-883` — `ttyConfirm` never wires the run's `AbortSignal` (CleanCtx has no `signal`, commands.ts:177-183), so the first Ctrl+C during the `aitm clean` prompt only prints "Cancelling" while readline keeps blocking; pass the signal into `rl.question(question, { signal })`.
- [severity: low] [category: resource] `commands.ts:203-208` — `drainStdin` waits for EOF with no TTY guard, so an interactive `aitm profile add x --api-key-stdin` (nothing piped) hangs silently until Ctrl+D; error out (or prompt) when `process.stdin.isTTY` is true.

## Architecture / SRP

- [severity: med] [category: arch] `commands.ts:1-1307` — The module map pins CLI to "arg parsing and exit codes only", but commands.ts is 1307 LOC mixing presentation (usage/cost formatting at 302-322, PR-link URL reconstruction at 270-295, model banner assembly at 235-263, secret masking/redaction at 1117-1165), business logic (style-digest orchestration via StyleDistiller at 1175-1211, takeover-state synthesis at 1235-1298, resume/supersede policy at 417-449), and wiring; split into `cli/format.ts` (or move into observability), move `defaultResolveStyle` next to StyleDistiller, and `synthesizeTakeoverState` into the loop/take-over module.
- [severity: med] [category: arch] `commands.ts:967-987` — `runMcpLogin` embeds OAuth *protocol* logic in the CLI layer: hardcoded `${origin}/oauth/authorize` / `/oauth/token` endpoint inference (no RFC 8414 discovery) and `client_id` scraped from a query param; move endpoint derivation into `src/mcp/oauth.ts` so the command is pure dispatch.
- [severity: med] [category: arch] `config-writer.ts:113-206 vs profiles.ts:239-285` — `parseValue`, `splitKey`, dotted get/set, `isNotFound`, `formatZodError`, and the readRaw JSON-object guard are duplicated nearly verbatim between ConfigWriter and ProfileManager (and `isNotFound`/`formatZodError` a third time in config-loader.ts:621-632); extract a shared `config/json-file.ts` + dotted-path helper — the duplication already diverged once (writer's setDottedKey vs profiles' setDotted have different guards).
- [severity: low] [category: arch] `commands.ts:335` and `config-loader.ts:124` — Warnings write straight to `process.stderr` (detector `onWarn`, ConfigLoader default `warn`) instead of the ctx stderr seam every other output uses, a hidden global that makes these warnings uncapturable in tests and un-redirectable; thread `ctx.stderr` into `buildDetectOpts` and pass a `warn` option when constructing ConfigLoader.
- [severity: low] [category: arch] `cli.ts:122-128` — `buildMcpLoginCtx` ignores its `ctx` argument and `MainCtx` has no `performOAuth` field, so the OAuth seam declared in `McpLoginCtx` (commands.ts:198-201) is unreachable through `main()` — which is exactly why runMcpLogin has no command-level test.
- [severity: low] [category: arch] `config-loader.ts:379-383` — `redactedMcpServers as typeof resolved.mcpServers` casts a `Record<string, unknown>` (headers/env replaced by the string `'<redacted>'`) into `McpServers`, an unsound widening skirting the no-cast house rule; type the snapshot as its own redacted shape instead of reusing `ResolvedConfig`.

## Tests / portability

- [severity: med] [category: portability] `commands.ts:976` (also type positions 199-200, 978) — Dynamic `import('../mcp/oauth.js')` uses a `.js` specifier while every other import in the package uses `.ts`; Bun and compiled dist resolve it, but Deno (a declared supported runtime) does not map `.js` → `.ts` without sloppy-imports, so `aitm mcp-login` breaks under Deno-from-source; use `'../mcp/oauth.ts'`.
- [severity: med] [category: test] `commands.test.ts` — `runMcpLogin` has zero tests (grep finds only arg-parsing cases in args.test.ts:607-644): the endpoint inference, `client_id` query-param extraction, snippet output, and error path are all uncovered; add tests through the `performOAuth` seam (after making it injectable via `main`, see above).
- [severity: low] [category: test] `config-writer.test.ts` / `profiles.test.ts` — Prototype-pollution tests cover key *paths* only (config-writer.test.ts:292-319, profiles.test.ts:170-173); there is no test for a hostile profile *name* (`profile add/use/set __proto__`), which is exactly the hole reported above — add name-based cases.
- [severity: low] [category: test] `cli.test.ts` — No test covers the entrypoint block's exit/flush ordering (cli.ts:195-211, the IIFE is untestable by construction); extracting it into an exported `runEntrypoint(proc)` would let the flush-before-exit and crash-path (exit 1) behavior be asserted.

Test pairing itself is clean: all 9 modules across both directories have a paired `*.test.ts` (255 tests total), and no `Bun.*` APIs, `any`, `as unknown as`, or default exports exist in either directory.

## Missing capabilities worth adding

- An `aitm config list --effective` (or `config resolve`) that prints the merged `ResolvedConfig` with per-key source labels — today `config list` shows one raw file per scope, and the only way to see actual precedence outcomes (profile vs global vs env vs default) is to start a run and read the snapshot.
- A `--` end-of-options separator across all subcommands, unlocking goals/criteria/config values that begin with `-` (currently unrepresentable).
- Profile-name validation plus a `profile rename`; and env-var overrides for common run settings (only `OPENROUTER_API_KEY`/`OPENROUTER_BASE_URL` exist — CI wrappers cannot set e.g. `maxSessions`/`logLevel` without writing files).
