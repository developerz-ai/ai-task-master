# Findings — cross-cutting architecture sweep

> Raw report from parallel audit agent. Scope: whole `packages/aitm/` — module-map conformance, dependency structure, portability, test pairing, export hygiene, out-of-scope creep.

## Findings

### 1. Module-map conformance (arch)

- [med] [category: arch] `/home/sebastian/workspace/developerz-ai/ai-task-master/CLAUDE.md` (module map) — The map lists 10 modules; `src/` has 19 dirs. The 10 undocumented dirs (`compaction`, `config`, `fs`, `mcp`, `observability`, `openrouter`, `plan`, `tools`, `workspace`, `testing`) are each individually coherent (one responsibility per dir, consistently `schema.ts` + feature files), so this is doc drift, not code drift. Fix: update the CLAUDE.md module map; it is the stated contract and is now ~50% stale.
- [med] [category: arch] `src/credentials/` + `src/openrouter/` + `src/config/provider-presets.ts` + `src/credentials/llm-fetch.ts` — CLAUDE.md says "Provider wiring lives in one place (Credentials)". It now lives in three dirs (credentials = model handles, openrouter = catalog/limits/server-tools, config = presets/profiles). The split is reasonable; the stated invariant is false. Fix: rewrite the invariant as "provider wiring = credentials + openrouter, presets in config" or merge presets into credentials.
- [high] [category: arch] `src/cli/commands.ts` (1307 lines) — CLAUDE.md: "CLI: arg parsing and exit codes only." This file constructs Credentials, ConfigLoader/Writer, ProfileManager, GitHubClient, StyleDistiller, OpenRouterClient, ModelLimitsRegistry, StateStore and defines `defaultRunLoop` — it is a second composition root, not arg parsing. Fix: move wiring into `loop/run-loop-adapter.ts` (the existing composition root) or a new `src/bootstrap/` module; leave `cli/` with args + dispatch + exit codes (`args.ts` at 550 lines is already the right shape).
- [med] [category: arch] `src/loop/run-loop-adapter.ts` (2049 lines, imports from 17 of 19 src dirs) — the de-facto composition root living inside `loop/`, which also contains the domain loop (`work-loop.ts`, `stage-handlers.ts`). Two reasons to change: loop semantics vs. dependency assembly. Fix: extract wiring to `src/composition/` (or `bootstrap/`) so `loop/` only drives the plan.
- [med] [category: arch] `src/subagents/worker.ts` (1484 lines) — worker agent definition + editor-fanout pool scheduler (`runEditorFanout`, ~line 977) + team-brief rendering in one file. Fix: split fanout/pool into `subagents/editor-fanout.ts`.
- [low] [category: arch] `src/config/config-loader.ts` (640 lines) — loads aitm config AND discovers/parses Claude Code's `~/.claude.json` / project MCP envelopes AND does secret redaction. Fix: extract `claude-code-config.ts` reader.
- [low] [category: arch] `src/agent-config/coding-style.ts` — the "find CLAUDE.md, return payload" module grew an LLM `StyleDistiller` (imports `reportUsage` from `subagents/factory.ts`). Detector and distiller are different reasons to change and the import inverts layering. Fix: inject `OnUsage` instead of importing from subagents, or move StyleDistiller under `subagents/`.
- [med] [category: arch] `src/templates/` — not empty: contains `oauth-success.html` / `oauth-error.html`. But `tsc` never copies them — `dist/templates` does not exist — so the published package (`files: ["dist"]`) always hits the `catch` fallback in `src/mcp/oauth.ts:106-116` (`getDefaultHtml`). The HTML files are dead assets and the inline fallback duplicates them. Fix: either add a copy step to `build` or delete the HTML files and keep only the inline strings.
- [low] [category: arch] `src/testing/temp-repo.ts` — test scaffolding compiled into the published artifact (`dist/testing/temp-repo.js`) but unreachable: `exports` maps only `"."` → `dist/index.js` and `index.ts` doesn't re-export it. Dead weight in the npm tarball. Fix: exclude `src/testing` from `tsconfig.build.json`.

### 2. Dependency structure (arch)

- [high] [category: arch] `src/cli/commands.ts:26-27` ↔ `src/loop/run-loop-adapter.ts:49` / `src/loop/merge-flow-adapter.ts:11` — genuine cli↔loop cycle: `commands.ts` value-imports both adapters, and both adapters import `RunLoopInput` / `RunMergeFlowInput` back from `cli/commands.ts` (defined at commands.ts:48 and :73). Type-only backward edges so it runs, but the loop's own input contract lives in the CLI. Fix: move both input types into `loop/`.
- [med] [category: arch] config ↔ credentials ↔ mcp dir-level cycle — `config/schema.ts:11` → `mcp/schema.ts`; `config/config-loader.ts:16` → `credentials/defaults.ts`; `credentials/credentials.ts:12` → `config/schema.ts`; `mcp/mcp-client.ts:16` → `credentials/credentials.ts` (Role). File-level it's acyclic (schemas are leaves) but the dir graph is tangled. Fix: move `Role` and shared schema types into a leaf `types`/`domain` module, or keep all schemas in `config/schema.ts`.
- [med] [category: arch] `src/config/config-loader.ts:17-21` — config (bottom layer) imports default constants from three higher layers: `DEFAULT_MAX_CI_FIX_ATTEMPTS` from `loop/constants.ts`, `DEFAULT_LLM_STEP_TIMEOUT_MS` from `subagents/factory.ts`, `DEFAULT_MCP_DEFER_TOOLS_OVER` from `mcp/mcp-client.ts`. Inverted layering for the sake of defaults. Fix: hoist defaults into `config/` (or `credentials/defaults.ts`-style leaf) and have loop/subagents/mcp import them downward.
- [med] [category: arch] state ↔ plan cycle — `state/state-store.ts:8` → `plan/plan-markdown.ts`, while `plan/schema.ts:6`, `plan/plan-graph.ts:5`, `plan/plan-markdown.ts:7` → `state/schema.ts`. Fix: `PrGroup`/`Task`/`TaskComplexity` are domain types, not persistence types — extract to a leaf `domain/` module both depend on.
- [low] [category: arch] state ↔ subagents type cycle — `state/rolling-context.ts:9` imports `WorkerDelivery` from `subagents/worker.ts` while `subagents/worker.ts:65` imports `state/schema.ts`. Fix: move `WorkerDelivery` into `state/schema.ts` or the proposed `domain/`.
- [low] [category: arch] tools ↔ subagents type cycle — `tools/github-thread-tool.ts:15` imports `GithubToolInput/Output` from `subagents/reviewer.ts`; `subagents/planner.ts:20-22` and `worker.ts:66-68` import tool I/O types from `tools/`. Fix: tool I/O types belong with the tool; move the Github thread types into `tools/github-thread-tool.ts` and have reviewer import them.
- [low] [category: arch] `src/state/schema.ts` — fan-in hub imported by plan, loop, observability, orchestrator, subagents, cli, resume-normalize. Acceptable as a schema leaf (it imports nothing upward), but it holds domain types under a persistence-named module; renaming/moving per the `domain/` suggestion resolves three of the cycles above at once.
- Clean leaves confirmed: `logger/`, `fs/`, `github/`, `openrouter/` import nothing upward (logger imports nothing relative at all). No god module that both fans in and fans out except the two composition roots flagged above.
- `packages/ai-claude-compat` (`@developerz.ai/ai-claude-compat`, version-locked 0.0.44) — Claude-Code-style agent primitives for the AI SDK: fs/bash/edit/search tools, subagent-as-tool factory, pool, skills/agents loaders, tool hooks. Imported by 17 shipped aitm files, overwhelmingly in `subagents/` plus loop/orchestrator/compaction; only leakage into low layers is `config/schema.ts:9` and `config/config-loader.ts:14` importing `CommandRule` (a type). Boundary is clean: aitm never reaches into `ai-claude-compat/src/*` deep paths, only the package export. One duplication smell: both packages ship an `atomic-write` (`aitm/src/fs/atomic-write.ts` vs `ai-claude-compat/src/atomic-write.ts`) — [low] consider re-exporting one from the other.

### 3. Portability

- [low] [category: portability] Zero hits for `Bun.`, `Deno.`, `import.meta.main` in shipped code (only comments referencing the ban). All node builtins consistently `node:`-prefixed. No `require()`, no `__dirname`, no top-level await. `cli/cli.ts:195` uses an `isEntrypoint(import.meta.url, process.argv[1])` helper instead of `import.meta.main` — correct cross-runtime pattern. This section is exemplary.
- [med] [category: portability] 16 shipped files use the `process` global with zero `from 'node:process'` imports anywhere. Fine on Bun/Node; on Deno the global only exists via the npm-compat layer (and natively only from Deno 2.0). The stated floor is "Deno ≥ 1.40", where a plain ESM import of these modules has no `process` global. Fix: either import `process` from `node:process` (works on all three) or document that Deno support means `deno run npm:@developerz.ai/aitm` only.
- [med] [category: portability] `src/mcp/oauth.ts:107-109` — `fileURLToPath(join(dirname(import.meta.url), '..', 'templates', ...))`: `path.join` on a `file:///` URL string collapses `///`→`/`, which happens to survive URL re-parsing on POSIX but breaks on Windows (drive-letter paths) — and the path never exists in dist anyway (see templates finding). Fix: `fileURLToPath(new URL('../templates/…', import.meta.url))`, plus ship or delete the templates.

All near-pure declarations; house rule says "no exceptions", so either add trivial tests or amend the rule for type/constant-only files. This contradicts CLAUDE.md "Tests must pass under both `bun test` and `node --test` … runtime portability is enforced by CI." package.json still advertises `"test": "bun test"`. Fix: update CLAUDE.md's testing claim to match reality, or restore a `bun test` job scoped to files unaffected by the bug; `test:node` and `test:integration` are real and run in CI (`ci.yml:73` + integration job).

### 6. Out-of-scope creep

- [high] [category: scope] `src/mcp/oauth.ts:76-77, 182-194` — spins up inbound HTTP: `net.createServer()` for port probing and `http.createServer(...).listen(port, 'localhost')` as an OAuth loopback-redirect listener, plus `openBrowser()`. CLAUDE.md v1 exclusions ban "Webhooks or any inbound HTTP" and instruct "stop and surface it". Mitigations: localhost-only, ephemeral, exists to serve aitm's *MCP-client* role (which is in scope), and the Provider-section "No OAuth" rule is about provider credentials, not MCP. Still, it is shipped inbound-HTTP code in a codebase whose rules say there is none. Surface for an explicit decision: either amend CLAUDE.md's exclusion to "no inbound HTTP *except* the localhost MCP OAuth loopback", or drop remote-OAuth MCP servers for v1.
- Clean otherwise: no mailbox/inbox code, no MCP *server* exposure (`McpServer` types in `mcp/schema.ts` are client-side config for external servers), no webhook endpoints, no Docker/devcontainer artifacts anywhere under `packages/aitm/`.

## Structural recommendations

- **Extract a leaf `domain/` module** holding `PrGroup`, `Task`, `TaskComplexity`, `Role`, `WorkerDelivery`, tool I/O types. This single move dissolves the state↔plan, state↔subagents, tools↔subagents, and config↔credentials↔mcp dir-level cycles — every cycle found is a shared-type cycle, not a logic cycle.
- **One composition root, not two.** Move the wiring halves of `cli/commands.ts` and `loop/run-loop-adapter.ts` into a dedicated `src/composition/` (or `bootstrap/`) module; `RunLoopInput`/`RunMergeFlowInput` move with it, killing the cli↔loop cycle and restoring "CLI = arg parsing and exit codes only".
- **Hoist all default constants into config-adjacent leaves** (`DEFAULT_MAX_CI_FIX_ATTEMPTS`, `DEFAULT_LLM_STEP_TIMEOUT_MS`, `DEFAULT_MCP_DEFER_TOOLS_OVER`) so `config/` never imports from loop/subagents/mcp.
- **Refresh CLAUDE.md's module map and testing/provider claims** — 10 of 19 dirs are undocumented, the "provider wiring in one place" and "bun test enforced by CI" statements are both currently false; the map is the audit baseline and it has drifted further than the code.
- **Resolve the templates/oauth decision**: delete `src/templates/*.html` + fix the URL-path construction in `mcp/oauth.ts`, and get an explicit CLAUDE.md carve-out (or removal) for the OAuth loopback HTTP listener — it is the only real scope-rule conflict in the package.

Overall shape: unusually strong conformance on the mechanical rules (zero `any`, zero default exports, zero Bun leaks, 96%+ test pairing). The system-level debt is concentrated in exactly two places — the double composition root with its cli↔loop cycle, and shared domain types scattered across `state/`/`subagents/`/`tools/` creating type-only cycles — plus documentation (CLAUDE.md) that has fallen behind a codebase that nearly doubled its module count.
